title: Framework islands
description: useTheme for React, Vue, Svelte and Solid, importable from astro-eclipse.
---

An island usually needs the current theme as reactive state, to render a different icon or label. `astro-eclipse` ships a `useTheme` hook for React, Vue, Svelte and Solid. Each one:

- reads the theme on the client only: `theme`, `preference` and `systemTheme` are `undefined` on the server and during hydration, so the first render matches the server HTML;
- unsubscribes when the component goes away;
- returns the applied theme (`light`, `dark`, never `system`), the visitor's preference (which may be `system`), the configured `themes` and the `systemTheme` (`light` or `dark`).

Each framework is an optional peer dependency. A project that does not use one installs nothing extra, and the hooks add nothing to the core client bundle.

To change the theme, call `toggleTheme` or `setTheme` from the event handler in the island as usual.

## React

```tsx src/components/ThemeButton.tsx
import { toggleTheme } from 'astro-eclipse/client'
import { useTheme } from 'astro-eclipse/react'

export function ThemeButton() {
  const { theme } = useTheme()
  return (
    <button type="button" onClick={(event) => toggleTheme({ origin: event.nativeEvent })}>
      {theme === 'dark' ? 'Switch to light' : 'Switch to dark'}
    </button>
  )
}
```

`event.nativeEvent` is the DOM `MouseEvent` that `origin` expects. The hook is built on `useSyncExternalStore` with an `undefined` server snapshot, so React reports no hydration mismatch. The real theme arrives right after hydration. Render the island with `client:only="react"` to skip the server render entirely.

## Vue

```vue src/components/ThemeButton.vue
<script setup lang="ts">
import { toggleTheme } from 'astro-eclipse/client'
import { useTheme } from 'astro-eclipse/vue'

const { theme } = useTheme()
</script>

<template>
  <button type="button" @click="toggleTheme({ origin: $event })">
    {{ theme === 'dark' ? 'Switch to light' : 'Switch to dark' }}
  </button>
</template>
```

`theme`, `preference` and `systemTheme` are read-only refs, `undefined` until the component mounts.

## Svelte

```svelte src/components/ThemeButton.svelte
<script lang="ts">
  import { toggleTheme } from 'astro-eclipse/client'
  import { useTheme } from 'astro-eclipse/svelte'

  const { theme } = useTheme()
</script>

<button type="button" onclick={(event) => toggleTheme({ origin: event })}>
  {$theme === 'dark' ? 'Switch to light' : 'Switch to dark'}
</button>
```

`theme`, `preference` and `systemTheme` are Svelte stores, so prefix them with `$` in the template. They work in Svelte 4 and 5. Call `useTheme()` while the component initialises.

## Solid

```tsx src/components/ThemeButton.tsx
import { toggleTheme } from 'astro-eclipse/client'
import { useTheme } from 'astro-eclipse/solid'

export function ThemeButton() {
  const { theme } = useTheme()
  return (
    <button type="button" onClick={(event) => toggleTheme({ origin: event })}>
      {theme() === 'dark' ? 'Switch to light' : 'Switch to dark'}
    </button>
  )
}
```

`theme`, `preference` and `systemTheme` are signals: call them, `theme()`.

## Write your own

For another framework, build the hook on `getTheme`, `getPreference`, `getSystemTheme` and `onThemeChange` from `astro-eclipse/client`. Read on the client only, and return the unsubscribe function from `onThemeChange` on teardown.

Anything that can listen to `document` can also use the event directly:

```ts
document.addEventListener('eclipse:change', (event) => {
  const { theme, preference } = (event as CustomEvent<{ theme: string; preference: string }>).detail
})
```

The event is fired by the [head script](/reference/head-script) as well, so it also covers changes from the system setting and from other tabs.
